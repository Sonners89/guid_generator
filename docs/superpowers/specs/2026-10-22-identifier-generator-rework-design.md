# Дизайн: переработка приложения "Генератор идентификаторов"

Дата: 2026-10-22
Ветка: `feature/add_unixTimeGenerator`

## Цель

Упростить главное окно приложения и выполнить ре-брендинг: приложение теперь
называется "Генератор идентификаторов", при открытии показывает только кнопку
`GUID`, по нажатию генерирует GUID и копирует его в буфер обмена.

## Требования

1. Название приложения меняется с "Генератор GUID" на "Генератор идентификаторов".
2. При открытии окно содержит только кнопку `GUID` (без поля с текстом).
3. По нажатию кнопки генерируется GUID и копируется в буфер обмена.

Уточнения, полученные в ходе обсуждения:

- В окне после запуска видна **только кнопка** `GUID`. Поле с текстом GUID
  удаляется.
- После нажатия показывается **модальное всплывающее окно**, в котором
  отображается **сам скопированный GUID**.
- При открытии окна до нажатия кнопки **ничего не происходит** (нет
  автогенерации, нет попапа).
- Название меняется **везде, где оно видно**, включая имена классов и артефактов.
- Класс `GUIDGenerator` переименовывается в `IdentifierGenerator`.
- Артефакты переименовываются в `IdentifierGenerator` (JAR и `.exe`).

## Выбранный подход

Подход A — минимальная переработка с сохранением текущей структуры. Логика
генерации остаётся в UI-классе.

Отклонённые альтернативы:

- **B** — вынести генерацию в отдельный класс `IdentifierService`. Отклонено как
  YAGNI: реальной потребности в тестах нет, а логика тривиальна.
- **C** — сразу добавить кнопку генерации Unix time. Отклонено: расширение scope
  за пределы текущих требований.

## Архитектура

Единственное Java-изменение — переименование класса `GUIDGenerator` в
`IdentifierGenerator`.

| Было | Стало |
|------|-------|
| `src/main/java/guidgenerator/GUIDGenerator.java` (класс `GUIDGenerator`) | `src/main/java/guidgenerator/IdentifierGenerator.java` (класс `IdentifierGenerator`) |
| `Main` создаёт `new GUIDGenerator()` | `Main` создаёт `new IdentifierGenerator()` |

Пакет `guidgenerator` не переименовывается. `Main` остаётся точкой входа.

## UI и поведение

**Окно**

- Заголовок: `"Генератор идентификаторов"`.
- Размер: `300×120` (уменьшен, поскольку текстового поля больше нет).
- Компоновка: `FlowLayout` с центрированием по умолчанию — кнопка по центру окна.
- Центрирование относительно экрана: `setLocationRelativeTo(null)`.

**Содержимое**

- Одна кнопка `JButton("GUID")`.

**Поведение**

- При открытии окна — никаких действий.
- По клику:
  1. `UUID.randomUUID().toString().toUpperCase()`;
  2. копирование значения в системный буфер обмена;
  3. показ модального диалога.

**Модальное окно**

- Заголовок: `"Готово"`.
- Текст: пояснение о копировании + сам GUID, например:

  ```
  GUID скопирован в буфер обмена:

  550E8400-E29B-41D4-A716-446655440000
  ```

**Удаляется**

- поле `JTextArea guidArea`;
- `JScrollPane`;
- метод `generateGuidSilently()`;
- флаг `isFirstGeneration`;
- `WindowAdapter` / `windowOpened`.

**Сохраняется (с изменениями)**

- `generateNewGuid()` — генерация и копирование;
- `copyToClipboard(String text)`;
- `showCopiedMessage(String guid)` — теперь принимает GUID и отображает его.

## Ре-брендинг сборки

`build.gradle`:

- `description = 'Генератор идентификаторов'`;
- `archiveBaseName = 'IdentifierGenerator'` (JAR → `IdentifierGenerator.jar`);
- `outfile = 'IdentifierGenerator.exe'`;
- путь к JAR в блоке `launch4j` → `${project.buildDir}/libs/IdentifierGenerator.jar`;
- `rename { 'IdentifierGenerator.jar' }` в задаче `prepareForLaunch4j`;
- `productName = 'Генератор идентификаторов'`;
- `Implementation-Title = 'Identifier Generator'`;
- `mainClassName` и manifest `Main-Class` остаются `guidgenerator.Main`.

`settings.gradle`:

- `rootProject.name = 'identifier-generator'`.

Не изменяются: иконка `icon.ico`, `companyName`, `copyright`, версия.

## Обработка ошибок

Новых сценариев не добавляется. Если буфер обмена недоступен, `setContents` может
бросить исключение — поведение остаётся таким же, как в текущей версии (без
обработки). Scope не расширяется.

## Тестирование

JUnit-зависимости уже подключены в `build.gradle`, тестов в проекте нет. В рамках
этого изменения автоматические тесты не добавляются: вся логика находится в
UI-классе (подход A), а `UUID.randomUUID()` тестировать нечего.

Ручная верификация после реализации:

1. `gradlew jar` → собирается `build/libs/IdentifierGenerator.jar`.
2. `java -jar build/libs/IdentifierGenerator.jar` → окно с заголовком
   "Генератор идентификаторов" и единственной кнопкой `GUID`.
3. Клик по `GUID` → GUID попадает в буфер обмена, появляется попап с этим GUID.
4. `gradlew buildExe` → собирается `IdentifierGenerator.exe`.

## Вне scope

- Генерация Unix time (несмотря на название ветки).
- Вынос логики генерации в отдельный класс / юнит-тесты.
- Обработка ошибок буфера обмена.
