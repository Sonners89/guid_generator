# Дизайн: добавление генератора unixTime

Дата: 2026-10-22
Ветка: `feature/add_unixTimeGenerator`

## Цель

Добавить в окно "Генератор идентификаторов" вторую кнопку — `unixTime`,
которая генерирует текущее время в микросекундах с эпохи Unix (16 цифр),
копирует значение в буфер обмена и показывает его в модальном окне.

## Требования

1. В окне появляется вторая кнопка `unixTime`.
2. По нажатию генерируется текущее время в микросекундах с эпохи Unix.
3. Значение копируется в буфер обмена и отображается в модальном окне.

Уточнения, полученные в ходе обсуждения:

- Поведение кнопки идентично кнопке `GUID`: генерация → буфер → модальный попап.
- Значение — микросекунды без выравнивания нулями (padding). Сегодня это 16
  цифр (~1.79e15).
- Порядок кнопок в окне: слева `GUID`, справа `unixTime`.
- Текст попапа для unixTime — аналог GUID-сообщения:
  `"unixTime скопирован в буфер обмена:\n\n<значение>"`.
- Размер окна увеличивается с `300×120` до `360×120`.

## Выбранный подход

Подход A — обобщить уже существующий метод показа сообщения.

- Добавляется метод `generateUnixTime()`.
- `showCopiedMessage` параметризуется: `showCopiedMessage(String label, String value)`.
- `copyToClipboard(String)` переиспользуется без изменений.

Отклонённые альтернативы:

- **B** — общий метод `generateAndShow(Supplier<String>, String)`. Отклонено как
  избыточная абстракция для двух вызовов (YAGNI).
- **C** — два независимых метода с дублированием копирования и показа. Отклонено:
  вносит копипасту там, где обобщение стоит дёшево.

## Архитектура

Новых файлов нет. Изменяется только
`src/main/java/guidgenerator/IdentifierGenerator.java`.

Изменения:

- новый метод `generateUnixTime()`;
- сигнатура `showCopiedMessage(String)` → `showCopiedMessage(String label, String value)`;
- GUID-путь вызывает `showCopiedMessage("GUID", guid)`;
- в `initUI()` добавляется вторая кнопка `unixTime` со своим обработчиком;
- размер окна `300×120` → `360×120`.

## Расчёт unixTime

```java
private void generateUnixTime() {
    Instant now = Instant.now();
    long micros = now.getEpochSecond() * 1_000_000L + now.getNano() / 1_000L;
    String value = String.valueOf(micros);
    copyToClipboard(value);
    showCopiedMessage("unixTime", value);
}
```

Требуется импорт `java.time.Instant`.

Формула: `epochSecond * 1_000_000 + nano / 1_000`. Значение — микросекунды без
padding; до ~2286 года оно занимает 16 цифр.

## UI

- Компоновка: `FlowLayout(FlowLayout.CENTER)`, обе кнопки добавляются
  последовательно:
  - `add(guidButton);`
  - `add(unixTimeButton);`
- Обе кнопки оформлены `Font("Arial", Font.BOLD, 14)`.
- Порядок: `GUID`, затем `unixTime`.
- Размер окна: `360×120`.

## Сообщение попапа

`showCopiedMessage(String label, String value)` формирует текст:

```
<label> скопирован в буфер обмена:

<value>
```

Заголовок диалога остаётся `"Готово"`, тип — `JOptionPane.INFORMATION_MESSAGE`.

## Обработка ошибок

Новых сценариев не добавляется. Если буфер обмена недоступен, `setContents`
может бросить исключение — поведение остаётся таким же, как в текущей версии
(без обработки).

## Тестирование

Автоматические тесты не добавляются: вся логика находится в UI-классе
(подход A), а `Instant.now()` и `UUID.randomUUID()` тестировать нечего.

Ручная верификация после реализации:

1. `./gradlew run` → окно `360×120` с двумя кнопками `GUID` и `unixTime`.
2. Клик по `GUID` → GUID попадает в буфер, попап с текстом
   `"GUID скопирован в буфер обмена:\n\n<GUID>"`.
3. Клик по `unixTime` → значение попадает в буфер, попап с текстом
   `"unixTime скопирован в буфер обмена:\n\n<значение>"`.

## Вне scope

- Выравнивание unixTime нулями до фиксированной длины.
- Иные форматы времени (секунды, миллисекунды, читаемая дата).
- Отдельный сервисный класс и юнит-тесты.
- Обработка ошибок буфера обмена.
